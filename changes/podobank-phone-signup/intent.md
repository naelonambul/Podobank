# Intent

## Problem

가상 은행 앱의 기본 금융 동작이 실제로 처리되고, 그 결과와 이벤트를 자동으로 관측할 수 있어야 한다. 앱 기능과 관측 파이프라인을 함께 보여주는 것이 포도뱅크 포트폴리오의 핵심이다. 신규 고객은 카카오 계정이 없어도 전화번호로 가입할 수 있어야 한다.

## Proposed outcome

포도뱅크(PodoBank)는 입출금·송금·대출·체크카드를 아우르는 가상 은행 앱이다. 이번 초기 구현은 입출금, 계좌 이체, 대출에 집중하며 체크카드는 제외한다. 결제 동작은 계좌 이체로 처리한다.

신규 고객은 전화번호 또는 카카오를 사용해 가입할 수 있다. 가입 화면은 두 경로를 같은 비중으로 안내한다. 전화번호 가입은 이름, 휴대전화번호, 필수 비밀번호와 나이·성별·혼인 상태·직장 유무를 받고, 가입이 완료되면 기본 계좌를 발급하고 로그인 상태로 전환한다. 카카오 가입은 기존 인증 흐름을 유지하고 휴대전화번호와 프로필 정보를 받아 기본 계좌를 발급한다. 모든 로그인 세션은 JWT HttpOnly 쿠키로 관리한다. 프로필 정보는 향후 상품 추천에 활용한다.

자동차 구매, 전세자금, 주택 매매 대출 상품을 미리 등록하며, 사용자가 상품을 골라 신청하면 은행 직원이 조건을 바꾸지 않고 승인하거나 거절한다. 승인 즉시 대출금은 계좌에 입금된다. 대출은 이자 없이 매월 1일 자동 상환하며, 첫 상환은 승인일로부터 한 달이 지난 뒤의 1일부터 시작한다. 월 상환액은 원금을 상환 개월 수로 나눈다.

가입 과정에서 휴대전화번호를 받아 중복을 확인하고, 계좌번호나 휴대전화번호 또는 사용자 목록으로 송금 상대를 찾을 수 있게 한다. SMS 인증은 하지 않으므로 전화번호 소유 여부를 확인하지 않는다. 실제 개인정보 대신 데모용 프로필과 다른 서비스에서 사용하지 않는 비밀번호를 사용한다.

앱은 금융 이벤트를 만드는 공장이고, 관측 스택은 생산 기록을 모아 보여주는 계기판이다. Grafana Alloy가 금융 이벤트와 지표를 자동 수집해 Loki와 Prometheus로 전달하고, Grafana에서 조회할 수 있게 한다.

## Affected users and systems

- 전화번호 또는 카카오로 포도뱅크에 가입하고 로그인하는 일반 고객
- 대출 신청을 검토하고 승인하는 은행 직원
- 금융 이벤트 흐름을 확인하는 개발자와 운영자
- Vue 3, FastAPI, MariaDB, SQLAlchemy Core, Alloy, Loki, Prometheus, Grafana로 구성된 시스템

## Constraints

- 이번 초기 구현 범위는 입출금, 계좌 이체, 대출이며 체크카드는 제외한다.
- 결제는 카드 대신 계좌 이체로 처리한다.
- 잔액이 부족한 출금·이체는 실패하고 계좌 잔액을 변경하지 않는다.
- 전화번호 가입과 카카오 가입 모두 일반 고객 계정을 만들고 기본 계좌를 하나 자동 발급한다.
- 전화번호 가입은 이름, 고유한 휴대전화번호, 필수 비밀번호, 나이, 성별(남성/여성), 혼인 상태(미혼/기혼), 직장 유무를 받는다. 가입 직후 해당 전화번호와 비밀번호로 로그인할 수 있다.
- 카카오 가입은 기존 인증·프로필 완성 흐름을 유지한다. 카카오 가입자의 로컬 로그인 비밀번호는 현재 제품 정책대로 선택 입력이며, 가입 이후에도 설정할 수 있다.
- 로그인 인증은 JWT HttpOnly 쿠키를 사용한다.
- SMS 인증 및 전화번호 소유 확인은 하지 않는다. 안내된 데모 환경에서는 실제 개인정보 대신 가상 프로필을 사용한다.
- 초기 백엔드부터 MariaDB를 유일한 데이터베이스로 사용하고 SQLAlchemy Core의 연결·트랜잭션 기능으로 직접 작성한 SQL을 실행한다. ORM은 사용하지 않는다.
- 가입 시 나이, 성별, 혼인 상태(미혼/기혼), 직장 유무를 받아 향후 상품 추천에 사용할 수 있도록 저장한다.
- 계정 등급은 일반 사용자와 은행 직원으로 구분하고, 대출 승인은 은행 직원만 할 수 있다. 공개 가입으로 은행 직원 계정을 만들 수 없다.
- 초기 데이터베이스에 은행 직원 계정을 한 명 등록한다.
- 대출 상품은 초기 데이터베이스에 미리 등록하고, 신청 후 상품 조건을 수정하지 않는다. 은행 직원은 승인 또는 거절만 한다.
- 초기 대출 상품은 자동차 구매, 전세자금, 주택 매매 세 종류다.
- 사용자는 신청 중이거나 상환 중인 대출을 동시에 하나만 가질 수 있다. 신청이 거절되거나 대출을 모두 상환한 뒤 다시 신청할 수 있다.
- 대출은 이자 없이 매월 1일 자동 상환한다. 첫 상환은 승인일로부터 한 달이 지난 뒤의 1일부터 시작한다. 월 상환액은 원금 ÷ 상환 개월 수며, 원금은 상환 개월 수로 나누어 떨어져야 한다.
- 잔액 부족으로 자동 상환에 실패하면 해당 회차를 연체 처리한다. 연체금은 월 상환액의 정수배 단위로 납부할 수 있다.
- 범위 안의 금융 동작 성공·실패 이벤트를 수동 작업 없이 자동 수집한다.
- 관측은 Grafana Alloy, Loki, Prometheus, Grafana를 사용한다.

## Out of scope

- 이번 초기 구현의 체크카드 기능
- 카드 결제 및 외부 결제망 연동
- 실제 금융기관과의 계좌 연동이나 실제 자금 결제
- SMS 발송, 인증 코드 및 전화번호 소유 확인
- 포트폴리오 데모에 필요하지 않은 금융 상품과 운영 기능

## Success criteria

- 랜딩 및 가입 시작 화면에서 전화번호 가입과 카카오 가입이 같은 비중으로 제공된다.
- 새 고객은 이름, 고유한 휴대전화번호, 필수 비밀번호와 프로필 정보로 가입할 수 있고 SMS 인증 없이 기본 계좌를 발급받으며 로그인 상태가 된다.
- 중복 전화번호는 가입되지 않으며 새 가입 고객은 전화번호와 비밀번호로 다시 로그인할 수 있다.
- 기존 카카오 로그인·가입, 선택적 비밀번호 설정, 기본 계좌 발급과 재로그인 동작은 계속 작동한다.
- 공개 가입으로 은행 직원 권한을 얻을 수 없다.
- 입출금과 계좌 이체가 잔액에 반영되고, 잔액 부족 거래는 실패한다.
- 사용자가 대출을 신청하고 은행 직원이 승인할 수 있으며, 승인 즉시 대출금이 계좌에 입금된다.
- 승인 대출은 매월 1일 자동 차감하며, 잔액 부족 회차는 연체되고 월 상환액의 정수배로 납부할 수 있다.
- 범위 안의 금융 동작 이벤트와 결과가 Alloy를 통해 자동 수집되어 Loki와 Prometheus에서 조회된다.
- Grafana에서 금융 이벤트와 기본 지표를 확인할 수 있다.
- 개발과 검증은 Docker Compose의 MariaDB와 샘플 데이터로 실행한다.

## Open questions

현재 백엔드 범위에서 추가로 결정할 제품 요구사항은 없다. 이벤트 필드, Prometheus 지표, Grafana 대시보드 세부사항은 백엔드 완료 후 관측 단계에서 정한다.
