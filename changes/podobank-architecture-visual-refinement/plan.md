# Podobank Architecture Diagram Refinement Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` to implement this plan task by task.

**Goal:** Show readable PNG previews of the ERD and system architecture in the README, with a compact Cloudflare boundary and recognizable official product marks in the OCI service cards.

**Architecture:** Keep the existing standalone HTML diagrams as editable sources and render local PNG snapshots with the repository's pinned Playwright version. In the system diagram, replace the oversized Cloudflare background panel with a slim edge boundary, group the UI and API Worker→VPC routes in compact double-outline groups, and add local official marks to the OCI program cards.

**Tech Stack:** HTML, CSS, local SVG/PNG brand assets, Node.js, Playwright, Chromium.

**Spec:** `docs/superpowers/specs/2026-11-04-podobank-architecture-visual-refinement-design.md`

## Release path

The README-preview PR #38 has already merged. This follow-up uses a new change packet and will be proposed in a new PR after its plan is approved and implementation is verified.

## Global Constraints

- Preserve all existing service names, routes, ports, arrows, data flows, and deployment facts.
- Use assets from the product vendor or official project repository; preserve aspect ratio and published colors, and record source and usage information.
- Keep all visual assets local; do not add runtime network requests or renderer dependencies.
- Keep readable text labels beside every logo.
- Before MariaDB-backed local verification, stop the live Podobank API, frontend, database, and dedicated API tunnel; use isolated test services and restore the prior Podobank state afterward. Leave shared services such as NPM, Jenkins, PostgreSQL, and SonarQube running.

## Review Focus

- UI and API Worker→VPC paths remain separate and point to the same OCI destinations as before.
- Logos remain legible, proportional, and paired with text labels.
- The full system diagram and both README previews remain unclipped at the existing capture viewports.
- Financial data and observability flows retain their existing direction and descriptions.
- Every vendored brand asset has a traceable official source and usage note.

## Risks and recovery

- Product marks may have distinct usage requirements or poor contrast at small sizes. Preserve each source's colors and proportions, keep names visible, and record asset guidance alongside the capture instructions.
- The slim edge boundary could make route grouping ambiguous. Keep two visibly separate double-outline groups and retain the UI/API labels on their arrows.
- The existing capture script renders both images. Confirm the ERD image remains unchanged; if it differs, determine whether the pinned browser output changed before including any ERD update.
- Before merge, restore the previous architecture HTML and PNG and remove only the new architecture asset files. After merge, make any correction in a new packet.
