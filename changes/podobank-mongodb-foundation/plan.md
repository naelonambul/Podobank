# MongoDB Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a private, persistent MongoDB service to the local Compose stack and provide FastAPI with connection settings for the later audit-event integration.

**Architecture:** MariaDB remains the financial source of truth. MongoDB is available on the Compose network at `mongo:27017`, with a named data volume and no published ports. The API receives `MONGO_URL` and `MONGO_DB_NAME`, but this change adds no MongoDB client code, outbox, event projection, or event writes.

**Tech Stack:** Docker Compose, official MongoDB image `mongo:7.0.45`, `mongosh`, existing Python observability smoke verifier.

**Spec:** `changes/podobank-mongodb-foundation/spec.md`

## Global Constraints

- MariaDB remains the only active store for financial state in this change.
- MongoDB image is pinned to `mongo:7.0.45`; its named volume mounts at `/data/db`. The server's current Docker host kernel prevents MongoDB 8.0 from starting; MongoDB 7.0 remains supported through 2027-08-31 and is the tested compatible patch for this foundation.
- The Compose service name is `mongo`; `MONGO_URL=mongodb://mongo:27017` and `MONGO_DB_NAME=podobank_events` are the connection settings.
- MongoDB publishes no host port and is not attached to the NPM external network.
- MongoDB is not a startup dependency of FastAPI; the current JSONL → Alloy → Loki/Prometheus pipeline stays unchanged.
- The local `.env` is ignored and must never be staged or committed. `.env.example` contains only local development values.
- This change installs MongoDB only. The transactional outbox, event projector, event API, and audit-event schema belong to a later approved change.

## Review Focus

- A local URI accidentally uses `localhost` from inside a container; config must use Compose DNS name `mongo`.
- MongoDB becomes reachable through a host-published port or NPM network; rendered Compose config must show neither.
- Container recreation loses database data; the smoke verifier must confirm a record survives a MongoDB restart.
- MongoDB being unavailable blocks API startup even though no current code uses it; API must not depend on MongoDB health.
- Installing the new service changes existing event behavior; the current observability smoke must still find its Loki events and Prometheus counters, while the Mongo smoke verifies only the database foundation.

## Risks and mitigations

- The named volume intentionally preserves MongoDB data across container recreation. Routine Compose shutdown must not use `down -v`; removing the volume is a separate destructive data operation.
- The service is unauthenticated in this development-only foundation and has no host or NPM port. Before real audit events are written or the service is used outside local development, the event-ingestion change must define credentials, authorization, retention, backups, and restore expectations.
- MongoDB can be healthy while the future event path is absent. The API must not claim that audit events are durable until the outbox and projector change is implemented and verified.

## Rollback or recovery

- To roll back the configuration, remove the MongoDB service, its API environment entries, and the `mongodb_data` declaration while leaving MariaDB and observability services unchanged.
- Preserve `mongodb_data` by default. Delete it only if the owner explicitly decides that its contents can be discarded.

## Open questions

None for this installation-only change. The approved spec leaves event payload design, outbox processing, MongoDB authorization, and retention policy to a later change.
